# Полное руководство по проекту Flask + Jinja2

## 1. Архитектура и структура проекта

**Проект построен по принципам чистой архитектуры (Clean Architecture):**

- **app/** — основной код приложения
  - **core/** — настройки, расширения, конфиг
  - **domain/** — бизнес-сущности, интерфейсы
  - **features/** — отдельные фичи (about, home, products, categories и др.)
  - **infra/** — инфраструктура (БД, репозитории)
  - **interfaces/** — контроллеры, шаблоны, статика
  - **shared/** — утилиты, общие функции
- **static/** — статика (css, js, картинки)
- **templates/** — HTML-шаблоны Jinja2
- **tests/** — тесты (unit, integration)
- **requirements.txt** — зависимости
- **run.py/app.py** — точка входа

## 2. Запуск и базовые действия

### 2.1. Установка и запуск

```bash
pip install -r requirements.txt
python run.py
# или
make run
```
- Откройте [http://localhost:5006](http://localhost:5006) в браузере.

### 2.2. Работа с Docker

```bash
docker-compose up --build -d
# или
make docker-dev
```

---

## 3. Основные области для изучения

### 3.1. Точка входа и создание приложения

- **run.py/app.py** — создаёт Flask-приложение через фабрику `create_app`.
- **app/core/__init__.py** — функция `create_app`, где:
  - создаётся объект Flask
  - подключаются расширения (SQLAlchemy, Migrate и др.)
  - регистрируются blueprints

### 3.2. Роутинг и обработка запросов

- В каждом модуле features (например, `app/features/products/routes.py`) определены роуты через декораторы `@bp.route`.
- Роуты вызывают сервисы (из `services.py`), которые реализуют бизнес-логику.

### 3.3. Работа с БД

- **app/infra/db/models.py** — SQLAlchemy-модели (таблицы)
- **app/infra/db/repositories.py** — CRUD-операции
- **app/domain/entities.py** — бизнес-сущности (например, Product, Category)
- **app/domain/interfaces.py** — интерфейсы для репозиториев

### 3.4. Бизнес-логика

- **app/features/*/services.py** — функции для работы с сущностями (например, фильтрация, сортировка, CRUD)
- **app/features/categories/** — уже реализован полный CRUD для категорий

### 3.5. Шаблоны и фронтенд

- **templates/** — шаблоны Jinja2
- **static/** — статика (css, js, картинки)
- Используйте наследование шаблонов и partials для DRY-кода

### 3.6. Тестирование

- **tests/unit/** — unit-тесты для сервисов и утилит
- **tests/integration/** — интеграционные тесты для роутов и бизнес-логики
- Запуск тестов:
  ```bash
  pytest
  # или
  make test
  ```

### 3.7. Миграции и работа с БД

- Используйте Flask-Migrate:
  ```bash
  make migrate-init      # инициализация миграций
  make migrate-create    # создать новую миграцию
  make migrate           # применить миграции
  make migrate-reset     # полный сброс БД (локально или в Docker)
  ```

## 4. Практические шаги для глубокого изучения

### 4.1. Изучите структуру проекта

- Пройдитесь по каждому основному файлу и подпапке, выпишите себе кратко, что где происходит.
- Нарисуйте себе схему (или mindmap) архитектуры.

### 4.2. Проследите путь запроса

- От браузера до базы данных и обратно:
  Пользователь → URL → Flask route → Service → Repository → DB → шаблон → браузер

### 4.3. Измените и добавьте что-то своё

- Измените текст на главной странице.
- Добавьте новый роут (например, `/hello`).
- Измените шаблон (например, добавьте новый блок на главную).

### 4.4. Добавьте новую сущность (если хочется потренироваться)

- Категории уже реализованы!
- Для тренировки: добавьте, например, сущность "Tag" или "Brand":
  - Модель в `models.py`
  - CRUD-операции в репозитории и сервисе
  - Роуты и шаблоны
  - Тесты

### 4.5. Поработайте с миграциями

- Добавьте новое поле в модель, создайте и примените миграцию.
- Проверьте, что поле появилось в БД.

### 4.6. Напишите тест

- Для сервиса, репозитория или роутов.
- Запустите тесты и убедитесь, что всё работает.

### 4.7. Добавьте CLI-команду

- В `app/interfaces/controllers/cli.py` добавьте новую команду (например, для сброса БД или генерации отчёта).
- Проверьте, что команда появляется в списке:
  ```bash
  flask --help
  ```

### 4.8. Проверьте работу с переменными окружения

- Измените `.env` или переменные окружения (например, смените БД, секретный ключ).
- Проверьте, что приложение подхватывает новые значения.

### 4.9. Проверьте обработку ошибок

- Попробуйте вызвать несуществующий роут.
- Добавьте обработку ошибок (например, 404, 500) и кастомные страницы ошибок.

### 4.10. Поработайте с деплоем и Docker

- Изучите Dockerfile и docker-compose.yml.
- Запустите проект через Docker.
- Проверьте, как подключается база данных в Docker.
